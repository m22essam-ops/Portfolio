Checking your server…

One moment.

Do this Start to finish, from nothing on screen to words on mohammedessam.com.

  1. Double-click Open the editor.command, in this folder. A black window opens and stays open. That window is the server: close it and everything below stops working. Two browser tabs open by themselves, the site and the editor.
  2. If the editor was already open, reload it before you start typing. It holds the whole site's text in memory. A tab you opened this morning still believes it is this morning.
  3. Write. Then press one of the two buttons at the top. Save locally writes this folder only, so your preview updates and the live site does not. Save to GitHub writes both, and that is the one that publishes.
  4. Read the line under the buttons. It says what happened to each destination. If something went wrong, that is where it says so.
  5. Wait a minute or two, then check the live site. GitHub rebuilds it after every save.

Three things that bite

Only ever 8888. The server takes the next free port if 8888 is busy, so it can end up on 8889 without saying anything is wrong. It looks completely normal. But your browser keeps the GitHub connection per address, so the editor on 8889 has never heard of your token and Save to GitHub just sits there. Two ways it happens: you start a second one while one is running, or something dead is still holding 8888. The second one is what had happened on 29 August, since 25 August. The launcher in this folder checks for both and says so instead of starting a server you cannot publish from.

Never open admin.html by double-clicking it. Opened as a file it gets its own private storage, so your GitHub connection is invisible to it, and Safari will not let it publish. Always go through 127.0.0.1:8888.

Words update fast, looks update slow. Your text is fetched with a stamp that changes every minute. The stylesheet is not. So if you change how something looks and the live site seems not to have noticed, it has: hold Shift and reload.
